Lecture/écriture de blocs Mifare Classic

Fil rouge : votre contrôle d’accès passe en version 2. L’autorisation ne repose plus sur l’UID, mais sur une donnée écrite dans la carte.

Cours

1. Structure d’une carte Mifare Classic 1K

La mémoire est organisée en 16 secteurs de 4 blocs de 16 octets, soit 64 blocs numérotés de 0 à 63. Le numéro de bloc absolu se calcule ainsi : secteur × 4 + bloc dans le secteur. Le bloc 0 contient l’UID et les données constructeur, en lecture seule sur une carte d’origine. Le dernier bloc de chaque secteur (blocs 3, 7, 11… 63), le trailer, stocke la clé A, les bits d’accès et la clé B.

2. Authentification par clé

Avant toute lecture ou écriture dans un secteur, le lecteur s’authentifie avec la clé A ou B (48 bits). La clé par défaut FFFFFFFFFFFF reste très répandue sur les cartes non reconfigurées, y compris, potentiellement, celles de la mallette. L’authentification repose sur un algorithme propriétaire, Crypto1, dont les faiblesses sont étudiées en séance 10.

3. Bits d’accès

Ils définissent, bloc par bloc, les droits de lecture et d’écriture associés à chaque clé. Une mauvaise configuration peut rendre un secteur accessible en écriture sans autorisation légitime, ou le verrouiller définitivement.

Atelier

Objectif : lire et écrire des données sur la carte Mifare Classic, puis les utiliser pour commander les LED.

Écrivez uniquement dans les blocs de données. Utilisez les blocs 4, 5 et 6 (secteur 1). N’écrivez jamais dans le bloc 0 ni dans un trailer (blocs 3, 7, 11, etc.) : une erreur sur les bits d’accès peut rendre le secteur définitivement inutilisable. Les cartes et badges de TP sont les seuls à manipuler.

Étape 1 : lire le bloc 0 et dumper la carte

Gardez le câblage de la séance 7. Téléversez Fichier → Exemples → MFRC522 → DumpInfo et présentez la carte. Repérez dans le secteur 0 le bloc 0 : UID, octet de contrôle (BCC), SAK et données constructeur. Notez aussi les secteurs qui affichent une erreur d’authentification : ils ne sont pas protégés par la clé par défaut.

Un « Timeout » ou une erreur CRC au milieu d’un secteur indique le plus souvent que la carte a bougé : posez-la à plat sur le module, sans la tenir, et refaites le dump avant de conclure.

ValeurExplication
Card UID: 09 74 2E A7UID de 4 octets, identifiant du tag. Il est recopié dans les octets 0 à 3 du bloc 0 et lisible sans clé.
Card SAK: 08Select Acknowledge : valeur renvoyée par le tag lors de sa sélection. 08 correspond à une Mifare Classic 1K.
PICC type: MIFARE 1KBType déduit par la bibliothèque à partir du SAK : 16 secteurs de 4 blocs de 16 octets, soit 1 Ko.
Sector 15, Block 6363 = 15 × 4 + 3 : dernier bloc du secteur 15, donc le trailer (clés et bits d’accès). Il en va de même pour les blocs 59 (secteur 14) et 55 (secteur 13).
Blocks 62, 61, 60Blocs de données du secteur 15, tous à 00 : aucune donnée n’a été écrite. Même chose pour 58-56 et 54-52.
Octets 0 à 5 du trailer : 00 00 00 00 00 00Clé A. Elle s’affiche à 00 car elle n’est jamais lisible. Ici, la clé réelle est FFFFFFFFFFFF, celle que DumpInfo a utilisée pour s’authentifier.
Octets 6 à 8 : FF 07 80Bits d’accès : 3 octets qui définissent les droits de chaque bloc du secteur. FF 07 80 est la configuration d’usine.
Octet 9 : 69Octet libre (general purpose byte), valeur d’usine, sans effet sur la sécurité.
Octets 10 à 15 : FF FF FF FF FF FFClé B, ici la valeur par défaut. Avec cette configuration, elle est lisible comme une donnée.
[ 0 0 1 ] sur un trailerBits d’accès C1 C2 C3 du trailer : la clé A n’est jamais lisible, mais la clé A permet de lire et de modifier les clés et les bits d’accès.
[ 0 0 0 ] sur un bloc de donnéesLecture, écriture, incrément et décrément autorisés avec la clé A ou la clé B.

À retenir : les trois secteurs sont identiques, donc la carte n’a jamais été reconfigurée. Toutes les clés valent FFFFFFFFFFFF et n’importe quel lecteur peut lire et écrire les blocs de données. C’est la faiblesse que vous exploiterez en séance 9 et corrigerez en séance 11.

Étape 2 : lire un bloc de données avec la clé A par défaut

#include <SPI.h>
#include <MFRC522.h>

#define SS_PIN 10
#define RST_PIN 9
const byte BLOC = 4;              // secteur 1, premier bloc de données

MFRC522 rfid(SS_PIN, RST_PIN);
MFRC522::MIFARE_Key cle;

void setup() {
  Serial.begin(9600);
  SPI.begin();
  rfid.PCD_Init();
  for (byte i = 0; i < 6; i++) cle.keyByte[i] = 0xFF;   // clé par défaut
  Serial.println(F("Presentez la carte..."));
}

void loop() {
  if (!rfid.PICC_IsNewCardPresent() || !rfid.PICC_ReadCardSerial()) return;

  // authentification du secteur du bloc avec la clé A
  MFRC522::StatusCode st = rfid.PCD_Authenticate(
      MFRC522::PICC_CMD_MF_AUTH_KEY_A, BLOC, &cle, &(rfid.uid));
  if (st != MFRC522::STATUS_OK) {
    Serial.print(F("Authentification : "));
    Serial.println(rfid.GetStatusCodeName(st));
  } else {
    byte tampon[18];              // 16 octets + 2 octets de CRC
    byte taille = sizeof(tampon);
    st = rfid.MIFARE_Read(BLOC, tampon, &taille);
    if (st == MFRC522::STATUS_OK) {
      Serial.print(F("Bloc 4 : "));
      for (byte i = 0; i < 16; i++) {
        if (tampon[i] < 0x10) Serial.print("0");
        Serial.print(tampon[i], HEX);
        Serial.print(" ");
      }
      Serial.println();
    } else {
      Serial.println(rfid.GetStatusCodeName(st));
    }
  }
  rfid.PICC_HaltA();
  rfid.PCD_StopCrypto1();
}

Pour afficher tout le secteur, vous pouvez aussi appeler rfid.PICC_DumpMifareClassicSectorToSerial(&(rfid.uid), &cle, 1); dans le loop.

Étape 3 : écrire un bloc puis le relire

Dans le sketch précédent, ajoutez ce tableau en haut et ces lignes juste après l’authentification réussie, avant la lecture. Choisissez votre propre valeur de 16 octets exactement (ici « ELEVE-01 » complété par des espaces).

// 16 octets exactement : à personnaliser
byte donnees[16] = {'E','L','E','V','E','-','0','1',
                    ' ',' ',' ',' ',' ',' ',' ',' '};

// à placer après l'authentification réussie, avant MIFARE_Read :
st = rfid.MIFARE_Write(BLOC, donnees, 16);
Serial.print(F("Ecriture : "));
Serial.println(rfid.GetStatusCodeName(st));

Relancez : la lecture suivante doit renvoyer les octets écrits (45 4C 45 56 45 2D 30 31 pour « ELEVE-01 »). Comparez avec le code ASCII de chaque caractère.

Étape 4 : contrôle d’accès v2

Le lecteur n’autorise plus selon l’UID, mais selon la donnée lue dans le bloc 4. Gardez les LED en D5 (verte) et D6 (rouge). Écrivez d’abord la valeur attendue sur la carte autorisée (étape 3), puis téléversez :

// à ajouter aux #define / variables de l'étape 2
const byte LED_VERTE = 5;
const byte LED_ROUGE = 6;
byte attendu[8] = {'E','L','E','V','E','-','0','1'};

// dans setup() : pinMode(LED_VERTE, OUTPUT); pinMode(LED_ROUGE, OUTPUT);

// dans loop(), à la place de l'affichage du bloc (après MIFARE_Read) :
bool autorise = (st == MFRC522::STATUS_OK) &&
                (memcmp(tampon, attendu, sizeof(attendu)) == 0);
Serial.println(autorise ? F("ACCES AUTORISE") : F("ACCES REFUSE"));
digitalWrite(autorise ? LED_VERTE : LED_ROUGE, HIGH);
delay(2000);
digitalWrite(LED_VERTE, LOW);
digitalWrite(LED_ROUGE, LOW);

Si l’authentification échoue, st n’est pas OK et la LED rouge s’allume : vérifiez que ce cas est bien couvert dans votre code.

Dépannage

  • Échec d’authentification : la clé du secteur n’est pas la clé par défaut, ou le bloc visé n’est pas dans le bon secteur.
  • Erreur de lecture ou d’écriture : gardez la carte immobile à 2-3 cm du module pendant toute l’opération.
  • Écriture refusée : bloc en lecture seule ou numéro de bloc incorrect (ne tentez pas le trailer).

Débrief sécurité

Répondez par écrit, en 2 à 3 phrases chacune :

  1. En quoi la v2 est-elle plus solide qu’une liste blanche d’UID, et pourquoi reste-t-elle fragile avec la clé par défaut ?
  2. Que doit connaître un attaquant pour lire ou modifier le bloc 4 de votre carte ?
  3. Que se passe-t-il si le contenu du bloc 4 est recopié sur une autre carte ? (séance 9)
Livrable : mini rapport de TP avec capture du bloc 0 et du dump, capture des données lues, écrites puis relues, liste des clés et des secteurs protégés rencontrés, code de la v2 commenté, photo des LED en fonctionnement, réponses au débrief.
